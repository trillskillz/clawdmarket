# Persisted Tempo fee observations

HTTP 1.104 records actual sender-paid pathUSD fees on Tempo chain 4217 in the existing nullable receipt/transfer evidence fields. No migration, signature, payment authority, retry, economic transition or spending allowance is added. Historical observations remain null; saved complete workflow receipts remain immutable.

The supported `tempo_pathusd_sender_fee_v1` model requires the configured canonical original receipt, transaction type 0x76, fee token pathUSD, and receipt fee payer equal to the original transaction sender. It also requires exactly one pathUSD `Transfer` from that payer to the protocol fee manager, attached to the same original transaction/block and log index. Its amount must equal `ceil(gasUsed * effectiveGasPrice / 10^12)` in six-decimal token units. Evidence records original chain/hash/block/payer, fee asset/manager/log, gas values, scale and exact charged units. Unknown, free, missing, sponsored by another payer, cross-token and contradictory observations stay null; approved ceilings never substitute for actual fees.

The rounding rule, receipt payer/token fields and fee transfer are checked against pinned official Tempo v1.16.0 sources: [gas calculation](https://github.com/tempoxyz/tempo/blob/v1.16.0/crates/primitives/src/transaction/mod.rs), [receipt](https://github.com/tempoxyz/tempo/blob/v1.16.0/crates/alloy/src/rpc/receipt.rs), [fee-manager constant](https://github.com/tempoxyz/tempo/blob/v1.16.0/crates/contracts/src/precompiles/mod.rs) and [independent balance/fee tests](https://github.com/tempoxyz/tempo/blob/v1.16.0/crates/node/tests/it/tip20_gas_fees.rs). The actual acceptance node is the previously checksum/attestation-verified binary at that tag, using owned disposable local funds only. This establishes the supported pinned model; it does not establish production fork compatibility.

Original hash proof reuses its verified canonical receipt. SDK funding attempts an additional read-only original-receipt observation; unavailable observation leaves fee evidence null and cannot restore send permission or replace the established funding proof. Existing settlement confirmation/reversion stores supported original treasury fee evidence beside its status. Caller input cannot supply observations. Ethereum L1/native/blob behavior remains unchanged.

Workflow reconciliation validates the model/rail, original transaction/payer, exact fee asset and integer arithmetic. Buyer and treasury fees are separate. Complete actual totals require recorded fees for every original payment and reconciled transfer; otherwise totals remain null with explicit partial/unknown status. Original cancelled/refunded attempts and treasury refunds stay included. Full original gross and worst-case lifetime fee reservations remain charged, even when actual fees are smaller. Missing or corrupted evidence cannot fabricate a measured aggregate.
