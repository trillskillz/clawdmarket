# Routing admission and monitoring (local contract 1.78)

Routing admission is independent of the ordinary marketplace payment pause. Initial and funded fallback reservations check durable `new_routes` control inside the capacity/order transaction. New EVM/Tempo intents, claims and actual guarded Tempo submissions check the same control. Existing checkout replay, original hash/receipt recovery, provider dispatch/delivery, explicit buyer acceptance, payout/refund outboxes and capacity reconciliation remain available. A valid already-paid proof can fund its original order while routing is held; revoked or otherwise invalid authority still uses the existing cancellation/refund path. A hold does not change those financial rules.

Apply additive migration `2026-10-03-route-admission-control-v1` before deploying. Readiness requires its control and append-only event tables. Application rollback must retain both tables. No payment, settlement or historical credit migration is part of this control.

The authenticated five-minute webhook cron checks gross mandate exposure, funding/claim linkage, confirmed-receipt consistency, backed-credit conservation, retry refund proof, stale claimed payments, uncertain routed settlement transfers and missing completed receipts. Invariant failures pause new routing. Pending claims/transfers and missing receipts become critical after 900 seconds; normal pending operations retain their wallet holds and existing reconciliation. Inspection failure records `MONITOR_FAILURE` when storage is available and never stops webhook/lease/artifact recovery. Missing controls deny new authority. Production (`VERCEL_ENV=production`) requires a financial observation no older than 900 seconds; absent or future timestamps hold admission until recovery.

Database holds, including an operator hold, reopen automatically only after three healthy observations spaced at least 30 seconds apart over a continuous window of at least 120 seconds. A financial failure, stale monitor or future timestamp resets that window. With the normal five-minute cron cadence, recovery requires three runs. This restores admission only: it cannot enable global routing, renew mandates, free uncertain claims or move funds. `CLAWDMARKET_ROUTE_EXECUTION_PAUSED=true` overrides database recovery and is the persistent operator/environment hold.

An authorized administrator can inspect `GET /api/admin/routing/pause` and submit `POST` with exactly `{"paused":true,"expected_revision":N}` or `false` to resume. Account bearer authentication or account cookie is required; cookies additionally require CSRF. Commands are bounded, rate limited and revision checked transactionally. An unhealthy or environment-held resume returns 409. Control responses expose revision, allowlisted reason, recovery progress and observation time, with private/no-store headers. Actor identity stays only in the private event table. Resume cannot clear an unresolved incident.

`GET /api/admin/routing/health` is an admin-only read-only snapshot. It reports fixed aggregate alert codes and counts for financial uncertainty, admission holds, provider acknowledgment/lease/deadline failures, missing or terminal attempts, stuck unfunded reservations, overdue checkouts, inactive mandate checkouts, webhook/settlement outbox age/failure, overdue verification and worker freshness. The existing hourly monitor consumes this snapshot and sends fixed routing labels/counts to its configured notification destination. It reports inspection failure without suppressing unrelated payment/RPC checks. No operator identity, owner value, objective, artifact bytes, payment hash, credential, endpoint or arbitrary stored error enters routing alerts. The protected read-only production audit shares the financial queries; it never writes controls or moves funds.

On `ROUTE_EXECUTION_PAUSED`, retry the same route after health recovery. Retain the original operation, signed bytes/hash, credential and mandate. A saved claim may return `send_allowed:false` and `recover_existing_payment`; never create a replacement payment. TypeScript clients receive the ordinary typed API error. This local outcome does not provide paid production or independent provider proof; those gates and the closed global rollout remain separate.
