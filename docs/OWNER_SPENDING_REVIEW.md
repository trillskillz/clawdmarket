# Owner-reviewed external service grants

The private `/organizations/{id}/spending-accounts` page lets the current owner grant deposited-credit purchasing or separately review configured Ethereum L1/Sepolia and Tempo wallet authority. Each grant names one already linked assigned buyer, original department/cost center, exact selected service/share, fee-inclusive purchase/day/month/lifetime ceilings and expiry. Existing exact human order approvals remain required.

For wallet authority, choose the configured rail/token, enter the buyer payer and both reserve floors, and set per-purchase and original lifetime gas/fee ceilings. Plain decimals must fit the configured precision exactly; the UI never rounds an excess fraction. The fixed configured treasury cannot be edited. Review the frozen chain/token metadata, payer/treasury, service scope, reserve floors and lifetime exposure, then explicitly confirm. This creates a restricted grant; funding remains a separate approved order and buyer-host signing operation.

Before submission the page saves only the exact reviewed body and original creation reference in the current tab's session storage. It saves the submission phase before POST. Reload restores those terms and requires fresh explicit confirmation. A lost reply preserves that same original reference. **Inspect original grant** uses the private owner GET with `client_reference` to find the record even outside the 100-record inventory. A confirmed original record clears the pending review; its credential cannot be reissued. Revoke that original credential and explicitly review another grant if its once-only key was lost. Retrying the original reviewed body returns the same grant and no secret after commit. No retry automatically creates another reference.

Returned secrets appear once only after a fresh private lookup verifies the exact original record. They never enter saved review state, inventory or logs. Reload/authorization denial clears visible keys and private data. Browser storage unavailable or malformed original review blocks new creation rather than discarding uncertainty. The page retains ordinary credit creation, private inventory and revocation.

HTTP 1.103 adds private DTO `client_reference` and frozen external `token_decimals`/`token_usd_price`, optional owner GET `client_reference`, and optional paired POST `expected_token_decimals`/`expected_token_usd_price`. If either expected field is supplied, both must match the configured metadata before insertion. Legacy clients may omit both; their authority fingerprints and scope remain unchanged. A definite metadata rejection on the first submission and private lookup showing no original record allow editing before a new reviewed submission. A prior unknown submission always retains its original terms, even if a later retry is definitively rejected. No schema change, wallet signature, transfer, general buyer authority or routing admission change is introduced. Production writes retain their existing closed gate.
